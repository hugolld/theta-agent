# 0007 — The eval suite is a custom two-layer harness

- **Status**: accepted (2026-11-04)
- **Context**: M6 must measure Theta twice over: catch drift when model-visible bytes change (skill edits, vendored re-syncs), and grade the agent's behavior on real tasks. The foundation question (#89) was pi-native or custom. The release survey (#81) found no eval or benchmark tooling anywhere in pi 1.2–1.4 — no runner, no snapshot tooling, no replay comparison. What ships are primitives: session files (the determinism base #85 pinned — `buildSessionContext()` reconstructs the model-visible context offline, entry ids are stable, compaction checkpoints replay as complete state, `fork`/`createBranchedSession` give shared-prefix sweeps), `models.classify()` (scoring), UsageEntry (cost), and the codemode worker queue (throughput). The clean-room rig (ADR 0005) exists as the dogfood and adversarial boundary.
- **Decision**: M6 builds a custom two-layer **eval suite** (GLOSSARY) on those primitives. Layer 1, the **replay net**: a keyless, deterministic regression net over normalized session recordings — the fixture format IS pi's session-file format, a typed normalization layer is Theta-built, and it runs host-side in the standard test suite (`npm test`); the rig's credential wall buys nothing keyless. Its replay is transcript replay (the durable-run glossary entry's mechanism) applied offline to fixtures: no model, no key. Layer 2, the **benchmark suite**: live-model graded task suites (CompBioBench-protocol flavor) running as a new mode of the clean-room rig (ADR 0005), carrying only the provider key. Grading is workspace-as-oracle primary — model prose and tool-result text do not prove the external effect — with `models.classify()` judging the subjective tasks under the standing adoption rule (it deletes a Theta-built judge harness); image input is available for figure judging, not required.

## Considered options

- **Pi-native as foundation** — nothing exists to found on: the survey's inventory carries no eval, replay, or benchmark tooling in any 1.2–1.4 release. Rejected.
- **The rig as harness** — the clean-room rig stays the dogfood and adversarial boundary; stretching it to host a keyless deterministic layer buys nothing, because the credential wall is its value and layer 1 needs no credentials. The live layer instead becomes a mode of the rig, inheriting its disposable checkout and credential handling. Rejected as foundation; adopted as host for layer 2 only.
- **Codemode as substrate** — the worker queue (`PI_CODEMODE_MAX_WORKERS`) is noted should parallel harness scripts ever need it; codemode itself is not adopted as the harness substrate. Rejected.

## Consequences

- **Capture policy**: snapshots come from dedicated rig captures of eval-shaped scenarios, never evidence derived from dogfood runs; a model-visible change (SKILL.md text, connector script, orchestrator doctrine, extension code) lands only with a fresh eval capture.
- **Benchmark scope**: single-model first — the campaign provider; provider is config, so multi-model is a later config loop on the milestone-boundary review wish list. Two-tier judging: the campaign provider's classify() for iteration and per-strike checks; a second, independent provider judges numbers destined for public surfaces (README benchmarks, `docs/performance.md`).
- **Cost reporting** rides pi's native UsageEntry ledger in session files — no custom cost tracking.
- **Survey inputs consumed**: the compaction fix (long benchmark legs compact reliably — never pass `reserveTokens`); the print-mode exit code (truncated rig responses fail loudly); resume-keeps-tools (multi-session benchmark legs keep Theta tools active).
- **M7 alignment**: the harness builds on the same session machinery every face wraps — one core, two faces (#88) — so the eval suite never grows a second core or a face of its own. Session files, never pi-durable: if evals ever need run-level (not transcript-level) replay, that is a pi-durable watch trigger (#85 records it), not a plan.
- **Drill legs**: the replay net lives inside `npm test`, so its snapshots and normalization are pins the mutation drill can flip — replay-net strikes carry drill legs in the #120/#122 attestation shape (scaffold scratch, one model-visible byte flipped, captured red set). The benchmark suite carries none: a live-model leg has no deterministic mutation to flip. Division of labor: the drill proves the test suite's pins bite; the replay net detects agent-visible drift; the benchmark suite measures the agent.
- **Spec detail deliberately left to M6**: normalization-token types, the net coverage list, capture-scenario design, and acceptance numbers measured before the spec lands.
