# Connector scripts

Invariants for `theta-lit-search`'s helper scripts — the shape the next connector copies — and, since M3, for the `theta-notebook` recorder as well (last bullet). What can be a suite check already is one: the offline tests drive every script at the process boundary (exit codes, stdout, stderr) against recorded fixtures. This note carries the judgement-call conventions that only sibling consistency enforces. Origin: the #18/#20 review passes and the M2 closeout rounds (two Claude rounds, one Codex round), whose real findings were convention drift and incomplete guards rather than bugs.

- **The exit-code table is the contract.** 0 success (zero results included — an answer, not a failure), 1 usage error, 2 transport failure, 3 API error inside an HTTP 200 body, 4 throttled. Codes 0–4 are shared by every connector; 5 (credentials unusable, message carries the key-request URL) exists only where a source demands a key — Semantic Scholar today. SKILL.md's table is the user-facing copy; keep the two in agreement.
- **`classify()` returns the parsed body or raises.** A dict for the JSON APIs, an Element for arXiv's Atom — never a flag, never an Optional. Failure is the raise (`ApiError.exit_code` carries the contract code). Endpoint-specific answer semantics live at the call site: Semantic Scholar's documented 404-not-found body is a genuine empty answer, so the DOI lookup goes through a caller-side `classify_lookup` wrapper — the wrapper is the pattern, a flag inside classify is not.
- **In-200 shape checks are typed, not presence-only.** The Codex closeout round caught `result.uids`/`esearchresult.idlist` accepted at any type — a string or dict iterates to zero items and answers a malformed 200 with a confident empty exit 0 — and a Semantic Scholar `{}` 200 extracting into a blank record with `paper_id: null`. The checks now require the list type, and every S2 paper object must carry the documented always-present `paperId`. A key that is merely present is not a shape.
- **Provenance is a repeat-the-call record.** One entry per request — `endpoint`, `params`, `url`, plus `headers` where credentials ride in headers (`{"x-api-key": "REDACTED"}`: the name survives, the value never does) — every map and URL through `redact_params`/`redact_url` first, attached as `provenance.calls` with an `accessed` date. The default text footer ends with a count line (`# N of M matches (retmax …)`, or `# N of M requested …` for identifier lookups) and a provenance line (`# provenance: <urls>; accessed <date>`); both shapes are load-bearing — consumers read them.
- **Validate every CLI argument on every path that accepts it.** The #20 review caught `--retmax` validated on the search subcommand only; the M2 closeout review fixed the same gap in pubmed.py and arxiv.py — all three connectors validate on every path now. A mutually exclusive group is not a reason to skip shared-argument validation on one branch. The Codex round also tightened `--doi` to reject raw `?`/`#`: URL delimiters never appear in a DOI suffix, and the suffix rides in the request path verbatim, so a pasted URL must fail as a usage error instead of silently issuing a different request.
- **At a fourth connector, hoist before copying.** `attach_provenance` and `author_line` are already pasted into all three scripts; a fourth connector moves them into `_common.py` first, not a fourth copy into its file.
- **The theta-notebook recorder follows these invariants too.** It makes no requests, so it shares only the codes that carry over (0 success, 1 usage) and documents its own failure domain as 2 (notebook failure) in its SKILL.md and docstring; the same seam test holds the two sites in agreement. The M4 job-record path (an assembled gateway job record as a method entry's evidence item, ADR 0004) joins the same contract: typed shape checks on the second evidence input, the `re-executed` grade refused without the fetched-artifact manifest, and the dogfood auditor mirroring the recorder's parser at the notebook leg.
